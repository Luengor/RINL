\chapter{Plan de seguridad}
\label{anexo4:cap:seguridad}
En este capítulo se describen los aspectos de seguridad más relevantes para el correcto
funcionamiento de la aplicación. Se abordarán temas importantes para la seguridad de la aplicación,
como el almacenamiento de datos, el saneamiento de entradas, la autenticación y autorización, y
la seguridad de las conexiones. Además, se discutirán las medidas implementadas para garantizar la
protección de los datos y la privacidad de los usuarios.

\section{Almacenamiento de datos}
\label{anexo4:sec:almacenamiento}
Uno de los tipos de vulnerabilidad más comunes en aplicaciones web es la exposición de grandes
cantidades de datos sensibles sobre usuarios, como contraseñas, correos electrónicos, números de
teléfono, etc. Para evitar este tipo de problemas, es fundamental implementar medidas de seguridad
adecuadas en el almacenamiento de datos.

En el caso del despliegue actual de la aplicación, la base de datos no es accesible directamente desde
Internet, lo que reduce significativamente el riesgo de exposición de datos sensibles, al no ser posible
acceder a esta desde el exterior. Sin embargo, puesto que se puede acceder a la base de datos desde la
\gls{api} de la aplicación, es importante implementar medidas de seguridad adicionales para proteger
la información almacenada.

\subsection{Datos sensibles}
\label{anexo4:sec:datos-sensibles}
Tratándose de una aplicación que realiza un seguimiento de la forma física de los usuarios y recopila
datos como peso, altura, edad, etc., es crucial proteger la información sensible de los usuarios. Por
esto, ciertos campos de datos sensibles se almacenan en la base de datos de forma cifrada. Esto permite
que, incluso si un atacante logra acceder a la base de datos, no podrá obtener información sensible
sin las claves de cifrado adecuadas.

En la aplicación se utiliza el paquete \texttt{sqlalchemy\_utils} para el cifrado de datos sensible. Este
utiliza internamente el algoritmo de cifrado simétrico \texttt{AES-256} para cifrar los datos antes de
introducirlos en la base de datos y justo antes de devolverlos al usuario. El cifrado se realiza
utilizando una clave de cifrado que se almacena en el entorno de ejecución de la aplicación, lo que
garantiza que no se almacena en la base de datos ni en el código fuente de la aplicación.

\subsection{Contraseñas}
\label{anexo4:sec:contrasenas}
Para el almacenamiento de contraseñas, se utiliza el algoritmo de \gls{hash} \texttt{argon2}. Argon2 fue el
algoritmo ganador del concurso \textit{Password Hashing Competition} en 2015 y es ampliamente recomendado
por su seguridad y resistencia a ataques de fuerza bruta \parencite{OWASPPasswordStorage}. El algoritmo
permite ajustar tres parámetros: el tiempo de ejecución, la memoria utilizada y el nivel de paralelismo,
lo que permite adaptarlo a las capacidades del hardware y aumentar la seguridad. Se puede ver la configuración
utilizada en el listado \ref{anexo4:lst:argon2-config}.

\begin{lstlisting}[
    language=Python,
    caption={Configuración de \texttt{argon2} en la aplicación}, captionpos=b,
    label={anexo4:lst:argon2-config}]
from passlib.context import CryptContext

pwd_context = CryptContext(
    schemes = ["argon2"], deprecated = "auto",
    argon2__type = "ID",
    argon2__time_cost = 2,
    argon2__memory_cost = 19456,
    argon2__parallelism = 1
)
\end{lstlisting}

\section{Autenticación y autorización}
\label{anexo4:sec:autenticacion}
La autenticación y autorización son dos aspectos fundamentales para garantizar la seguridad de los
sistemas informáticos. La primera se encarga de verificar la identidad de un usuario, de confirmar
que es quien dice ser, mientras que la segunda se encarga de determinar que acciones puede realizar
ese usuario una vez se ha autenticado.

En esta aplicación, se utiliza un sistema de autenticación basado en tokens JWT para gestionar las
sesiones de usuario y otras funcionalidades relacionadas con la seguridad. Por otro lado, en
cuanto a la autorización, en la aplicación no existen diferentes roles de usuario, solo se
distingue entre usuarios que hayan verificado su correo electrónico y aquellos que no lo han hecho.

\subsection{JWT}
\label{anexo4:sec:jwt}
El sistema de autenticación de la aplicación se basa en el uso de tokens JWT (JSON Web Tokens).
Un token JWT es una forma compacta y segura de representar y transmitir información entre dos
partes. Estos tokens contienen una serie de afirmaciones (claims) que pueden ser verificadas y
firmadas digitalmente, lo que garantiza la integridad y autenticidad de la información contenida
en ellos \parencite{rfc7519}.

En la aplicación se usan tokens para varias labores, como la autenticación de usuarios, la
verificación de correos electrónicos y la actualización de estos. El procedimiento que se sigue
para el caso de la autenticación de usuarios es el siguiente:
\begin{enumerate}
    \item El usuario envía sus credenciales (correo electrónico y contraseña) a la API.
    \item La API verifica las credenciales y, si son correctas, genera un token JWT que contiene
          el identificador del usuario y la fecha de expiración del token. Este token se firma
          con una clave secreta que solo la API conoce para poder verificar su autenticidad.
    \item El usuario recibe el token y lo almacena en su cliente.
    \item En cada solicitud posterior a la API, el usuario incluye el token en el encabezado de
          autorización de la solicitud.
    \item La API verifica el token, comprobando su firma y asegurándose de que no ha expirado. Si
          el token es válido, la API permite el acceso a los recursos solicitados. Si no, responde
          con un error de autenticación.
\end{enumerate}

El mayor riesgo de seguridad asociado al uso de tokens JWT es el robo del token por parte de un
atacante. Para que un ataque de este tipo tenga éxito, el atacante debe conseguir acceder al token
del usuario antes de que este expire (en la aplicación, el tiempo de expiración de \textit{todos}
los tokens es solo de 15 minutos). Es un riesgo que se mitiga utilizando HTTPS para cifrar las
comunicaciones entre el cliente y la API y teniendo en cuenta que, el almacenamiento de los tokens
en el cliente, es privado para cada sitio web.

Las maneras en las que un atacante podría robar un token se limitarían entonces a impersonar la
página web de la aplicación para robar el usuario y contraseña y obtener ellos mismos el token, o
ganar acceso al dispositivo del usuario para robar el token directamente.

\subsection{Verificación}
\label{anexo4:sec:verificacion}
Para hacer uso de la mayoría de las funcionalidades de la aplicación es necesario que el usuario
verifique su correo electrónico. Para ello, se envía un correo electrónico al usuario con un
enlace para verificarlo. Cabe destacar que, para poder utilizar dicho enlace, el usuario debe
haber iniciado sesión en la aplicación, evitando así que el receptor incorrecto de un correo
de verificación pueda hacer uso de él.

Esta obligación de verificación es una medida de seguridad que ayuda a prevenir el registro de
cuentas falsas o spam, ya que requiere que el usuario tenga acceso al correo electrónico
proporcionado durante el registro para poder hacer uso de él.

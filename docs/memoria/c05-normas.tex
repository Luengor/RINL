\section{Métodos}
\label{sec:metodos}
Para el desarrollo del proyecto se ha seguido una metodología ágil, en concreto Scrum. Se escogió
una metodología ágil debido a que es de gran utilidad para proyectos de desarrollo en los que
pueden surgir cambios en los requisitos o problemas técnicos no previstos que afectarían mucho
a una planificación predictiva \parencite{robert2003agile}. Scrum por su parte es un marco de trabajo
ligero que agrupa el trabajo en ciclos cortos llamados sprints, con duración entre una y cuatro semanas,
donde se planifica el trabajo a realizar y se revisa al final del ciclo \parencite{schwaber2020scrum}.

Este nivel reducido de planificación es más sencillo de realizar y permite un mayor grado de
adaptabilidad a los cambios. Para más información sobre la planificación del proyecto, ver el \tercerAnexo.

\subsection{Desarrollo del \Gls{backend}}
\label{sec:desarrollo-api}
Para el desarrollo del \gls{backend} de la aplicación se ha utilizado el \gls{framework} \tech{FastAPI}
{https://fastapi.tiangolo.com/}, un \gls{framework} moderno y rápido para construir API con Python 3.7+
basado en estándares como \texttt{OpenAPI} y \texttt{JSON Schema} \parencite{fastapi}.

Junto a este framework, se han utilizado varias bibliotecas y herramientas para facilitar el desarrollo
y la gestión del proyecto. Entre ellas, destacan:
\begin{itemize}
    \item \texttt{Pydantic}: una biblioteca para la validación de datos. Utilizada para definir los modelos de
        datos de entrada y salida de la \gls{api}, garantizando que los datos cumplen con los tipos y formatos
        esperados.

    \item \texttt{PyJWT}: una biblioteca para la creación y verificación de tokens JWT (JSON Web Tokens).
        Utilizada para la autenticación y autorización de usuarios en la \gls{api}.

    \item \texttt{Pytest}: una biblioteca para la realización de pruebas unitarias y de integración.
        Se integra de manera muy sencilla con el código existente, permitiendo definir pruebas para
        las diferentes funcionalidades de la \gls{api} y ejecutarlas de forma automática.

    \item \texttt{SQLAlchemy}: el \gls{ORM} utilizado para interactuar con la base de datos de forma
        sencilla y segura. Permite interactuar con varios tipos de bases de datos relacionales,
        para interactuar con PostgreSQL se ha utilizado el paquete \texttt{psycopg2}.

    \item \texttt{Uvicorn}: un servidor \gls{asgi} ligero y rápido para ejecutar aplicaciones como FastAPI.
        Es utilizado para servir la \gls{api} tanto en producción como en desarrollo, donde además permite
        la recarga automática del código al detectar cambios, facilitando el desarrollo.
\end{itemize}

Como se ha mencionado entre la lista de herramientas, se ha utilizado \tech{PostgreSQL}
{https://www.postgresql.org/} como sistema de gestión de bases de datos relacional para almacenar
la información de la aplicación.

Para la gestión de las dependencias del proyecto, así como para la creación de un entorno virtual se
ha utilizado \tech{UV}{https://docs.astral.sh/uv/}. Esta herramienta permite gestionar las dependencias
de forma sencilla y rápida, además de crear un entorno virtual aislado para el proyecto. Esto es
especialmente útil para evitar conflictos entre las dependencias de diferentes proyectos y garantizar
que el proyecto se ejecuta en un entorno controlado y reproducible. Además, es mucho más rápido que el
resto de gestores de dependencias \parencite{Katabattuni2024Nov}.

\subsection{Videojuego}
\label{sec:videojuego}
Para el desarrollo del videojuego se ha utilizado el motor de videojuegos \tech{Unity}
{https://unity.com/}, un motor de videojuegos multiplataforma que permite crear juegos en 2D y 3D.
Unity es ampliamente utilizado en la industria de los videojuegos y ofrece una gran cantidad de
herramientas y recursos para hacer videojuegos de forma sencilla y rápida.

Junto a Unity, se ha utilizado el lenguaje de programación \texttt{C\#} para el desarrollo del
videojuego, ya que es el lenguaje de programación principal de Unity y permite acceder a todas
las funcionalidades del motor.

\section{Modelos}
\label{sec:modelos}
Para la detección de posturas en tiempo real se ha utilizado una red neuronal convolucional,
BlazePose, un modelo de aprendizaje profundo diseñado para la detección de posturas humanas en
imágenes y vídeos \parencites{bazarevsky2020blazepose}{xu2020ghum}. Este modelo es capaz de
detectar y rastrear 33 puntos clave (ver figura \ref{fig:blazepose}) del cuerpo humano en tiempo
real, lo que lo hace ideal para aplicaciones de seguimiento de posturas y análisis de movimiento.
Además, incluye junto a las posiciones de los puntos clave en la imagen, la confianza de la
detección y la visibilidad de cada punto, así como una representación de los puntos en 3D.

Las razones para escoger BlazePose sobre otros modelos de detección de posturas se detallan
en el capítulo \textit{\nameref{c08:sec:alternativas-tecnologicas}}, en el apartado dedicado al modelo de
detección de posturas (\ref{c08:subsubsec:mediapipe}). De forma resumida, BlazePose ofrecía un
buen equilibrio entre precisión y velocidad de procesamiento, lo que lo hacía adecuado para esta
aplicación.

\section{Métricas}
\label{sec:metricas}
Durante el desarrollo del proyecto era necesario evaluar el correcto funcionamiento de la aplicación,
así como la precisión de la detección de posturas. Aunque para el segundo de estos aspectos el
proceso de validación consistió en probar la aplicación múltiples veces durante el desarrollo de
la misma, para el primero se definieron una serie de pruebas unitarias para garantizar el correcto
funcionamiento de la \gls{api}. Las pruebas unitarias se comenzaron a definir en los primeros sprints
del desarrollo, una vez se creó la estructura de la \gls{api} y se implementaron las primeras
funciones. Estas pruebas, que se ejecutan de manera casi automática, permiten verificar que cada nueva
versión del código no introduce errores en las funcionalidades ya implementadas.
